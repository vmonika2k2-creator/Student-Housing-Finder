PROJECT CONTEXT
This is "Student Housing Finder" (brand name "room.for"), a pnpm workspace with:
- artifacts/student-housing: React front end (pages in src/pages, admin page is Admin.tsx)
- artifacts/api-server: Express API (routes in src/routes/student-housing)
- lib/db: PostgreSQL with Drizzle
- lib/api-spec/openapi.yaml: API contract (client and schemas are generated from it)
Students browse demo rental listings and chat with an AI housing guide that calls OpenAI
on the server. The GitHub repo is vmonika2k2-creator/Student-Housing-Finder and it is
connected to this Replit project. The live site is
https://student-housing-finder--taramonika.replit.app

WHAT WAS BUILT (already merged into main)
An admin panel at /admin, protected by a password, that lets the admin control how the
chat agent behaves, with these sections:
1. Persona (text)
2. Tone (text)
3. Empathy scale 0-10, with an example reply to write for each of 5 stages
   (0-1, 2-3, 4-6, 7-8, 9-10). The stage that matches the slider is highlighted.
4. Initiative scale 0-10 (passive to goal-oriented), with a "Goal for the conversation" textbox.
There is also "Save settings" and "Reset to defaults".

HOW IT WORKS
- Login: POST /api/housing/admin/session checks the ADMIN_PASSWORD secret and sets a
  signed cookie. GET /api/housing/admin/session checks the cookie.
- Settings: GET and PUT /api/housing/admin/agent-settings read and save one row (id = 1)
  in the table student_housing_agent_settings (defined in lib/db/src/schema/agentSettings.ts).
- Chat: POST /api/housing/assistant loads the saved settings from the database and adds
  them to the system prompt sent to OpenAI (see artifacts/api-server/src/lib/agentSettings.ts).
  The settings change style only. They must never override the accuracy and safety rules.
- The server creates or upgrades the table by itself if it is missing, and it falls back
  to defaults in the chat if the settings cannot be read.
